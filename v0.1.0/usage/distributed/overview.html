Running a distributed solve

A distributed solve uses the same solve you already know. You keep the model and the case, and you swap the algorithm: instead of centralized(), you pass admm(...) or aladin(...). Lirion then splits the network into zones, each zone solves its own local OPF, and the zones coordinate on the boundary until they agree.

The distributed algorithms run on the DC, AC, SOCWR, and SOCWRNL models.

Important

The runs below are simple examples. The way you configure a distributed algorithm changes the optimization problem itself, so reading the next pages first is strongly recommended. See Coupling and sectioning, ADMM settings, and ALADIN settings. For the theory behind the algorithms, see ADMM and ALADIN.

With ADMM

admm() defaults to coupling = :hybrid and sectioning = :tie_line.

using Lirion

result = solve("paper/cases/partitioned/case24_ieee_rts/std/k3/case.m";
    model = ac(),
    algorithm = admm(rho = 1e3),
)

With ALADIN

aladin() defaults to coupling = :state and sectioning = :tie_line.

using Lirion

result = solve("paper/cases/partitioned/case24_ieee_rts/std/k3/case.m";
    model = dc(),
    algorithm = aladin(),
)

Reading the result

A distributed run returns the same LirionResult as a centralized one, plus the per-zone tables and the convergence history. For the extra fields and how to read them, see the Decentralized section of Results.
